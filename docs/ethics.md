# 伦理评估

本文件对应项目目标中"评估当前过滤行为的伦理合理性，并提出恢复客观性的机制"。

## 1. 当前的过滤行为为何在伦理上有问题

搜索引擎按**语义相似性**和**流量/商业因素**排序，缺少真实性验证；LLM 又基于
**相关性与受欢迎程度**进一步筛选。伦理风险包括：

- **认知风险放大**：高流量但低质量的内容被反复保留，形成回声室。
- **责任缺失**：模型把"选择/丢弃"包装成中性的信息处理，实际影响了公众认知。
- **不可追溯**：用户看不到"为什么这条被保留、那条被丢弃"。
- **迎合用户**：以满意度为目标会倾向保留顺耳但错误的断言。

## 2. 本 Agent 的伦理立场（七条）

1. **评估证据质量**，而非只评估相关性。
2. **推理可追溯、可质疑**：所有判断依据随结果返回。
3. **明示不确定性**：区分事实 / 推理 / 意见 / 推论，并给出边界条件。
4. **拒绝无依据的断言**：可证伪而毫无证据的陈述直接剔除，并压低 Factuality（事实性）。
5. **诚实性须可核验**：回答必须交代自己的底细——无依据断言不加限定即视为不诚实（`H1`），传播度驱动、来源冲突、检索范围都应显式披露（`H2`–`H4`）；日志凭证即证据（`criteria` / `layers` / `revision_log`）。
6. **外部 judge 只作接地复核，不冒充事实判定**：Ragas / TruLens 锚定的是传入的检索上下文（内部忠实性），其结论单列为 `grounding`，**不得**覆盖锚定外部可靠来源的五级判决。否则就会出现"检索集偏窄 → 把客观为真的陈述判成不可信"的隐性误判。
7. **认知准确性优先于用户满意度**：不以"顺耳"为保留标准。

## 3. 机制设计如何落实这些立场

| 伦理主张 | 机制 | 代码位置 |
|----------|------|----------|
| 证据质量优先 | 来源可靠性分级 + 可靠性加权支持度（非计数加权） | `rva/stages/verify.py` |
| 抵抗流量偏置 | 流行度偏置检测 + `D3` 降级 | `rva/stages/verify.py`、`output.py` |
| 可追溯 | 每条陈述返回 `cues`、`criteria`、`coverage`、`score_breakdown` | 三个阶段 |
| 可质疑 | `challengeable=True` + 明示规则表 | `rva/stages/output.py` |
| 明示不确定 | 类型标签 + 置信度 + `boundary_conditions` | `decompose.py`、`output.py` |
| 拒绝无依据断言 | `X2`；Factuality 的 `unsupported` 计 0 | `output.py`、`evaluate.py` |
| 不混淆接地与事实 | judge 结果单列 `GroundingResult`，不写入 `FactualityResult` | `evaluate.py`、`integrations.py`、`models.py` |
| 诚实性可核验 | Step-4 四查 `unsupported_rejected` / `uncertainty_marked` / `conflicts_preserved` / `sycophancy_checked`（`H1`–`H4`）+ `H5` 相关性 + 修订日志 | `honesty.py`、`revise.py` |
| 准确性优先 | 主观意见一律 `contextualize`（不作为知识） | `output.py` |

## 4. 已知的伦理张力

- **"客观性"本身不中立**：来源分级内嵌价值判断（如把 .gov 视为高可靠）。本实现将其
  **显式化、可替换**，以便被审计和辩论，而不是隐藏在排序算法里。
- **过度剔除的风险**：规则过严会压制合法但非主流的声音。因此系统倾向 `demote / contextualize`
  （降级、标注）而非直接删除，并暴露决策理由。
- **权威偏置**：以机构层级赋分可能系统性低估独立研究者；`registry` 可被替换正是为缓解此点。
- **覆盖≠真值**：词汇重叠只是"来源确实在谈论此事"的代理指标，不等于支持。故所有结论都附带
  "仅反映当前检索集"的边界条件。
- **指标被误读的风险**：本指标锚定**外部可靠来源**（事实效度），但仍是"相对当前检索集"的判断：`Unsupported` 只表示"检索到的可靠来源未能证实"，不等于是假；若检索集本身有偏，判定也会被误导。
  因此必须与来源分级、偏置检测联合解读。
- **把 grounding 当事实效度的风险**：Ragas / TruLens 衡量的是"是否扎根于给定上下文"。
  一个完全扎根于偏见检索集的陈述可以是完全"grounded"却在事实上为假（反之亦然）。
  故两者的分数**分开报告、绝不合并**：`grounding` 用于检查"回答有没有忠于它的材料"，
  `factuality` 用于检查"材料本身是否可靠、陈述是否为真"。混用会制造"高 grounding = 高真实性"的错觉。
- **责任归属**：本 Agent 是**辅助审查**，不能替代人工判断；最终责任仍在部署方与用户。

## 5. 面向公众的认知保护

- 分层证据界面让用户看到一级证据、弱证据与冲突来源，而不是一个不透明的"答案"。
- 可信度评分是**证据强度**的表达，不是"真理概率"；文档与输出中均如此标注。
- 对被流量放大的错误断言，系统会显式指出"支持与流行度相关，而非准确性"。
- 来源锚定的准确率把"无可靠来源证实的断言"变成一个可量化的公开数字，便于问责。

## 6. 后续伦理工作建议

- 建立来源分级的**多方治理机制**，避免单一机构定义"可靠"。
- 对 `drop` 决策引入**人工复核与申诉**通道。
- 记录并公开**审计日志**，用于研究模型筛选行为的社会影响。
- 与领域专家合作，为不同学科定制可靠性口径与阈值，并校准 Factuality 判据。
